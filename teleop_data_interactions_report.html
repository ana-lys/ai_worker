5.1 ZMQ framed structs — ffw_zmqinterface/protocol.py

One ZMQ message = one framed struct: fixed 12-byte header + payload. ZMQ preserves message boundaries so no further framing is needed.

Header (every message):
  [0:4]   type      int32  little-endian   -- MSG_* dispatch id
  [4:12]  timestamp float64 epoch seconds   -- sender clock; makes re-assertions unique for byte-dedup

RPY convention:  extrinsic XYZ  →  R = Rx(roll)·Ry(pitch)·Rz(yaw)   (matches joy_hand rpy_to_matrix)
MSGidPortdirFrame bytesPayload layout
MSG_OBS16001 (PUB)robot → ctrl724 B89 doubles: EE block [0:14] = ee0(6) grip0 ee1(6) grip1 — ee0 = right, ee1 = left, grip = 0.0 open…1.0 close; joint block [14:89] = 25× pos, vel, effort in JOINT_STATE_NAMES order.
MSG_CONTROL_CMD26002 (SUB)ctrl → robot124 B14 doubles: ee0(6) grip0 ee1(6) grip1 — absolute EE goals + grippers (same 14-layout as Obs EE block).
MSG_PRIV36003 (PUB)robot → ctrl236 B28 doubles: HeadCamTf [0:16] row-major 4×4 (R 3×3 + translation col 3 + last row 0 0 0 1); EEDelta [16:28] = d0(6), d1(6) — per-tick map-frame commanded deltas (m / rad), all-zeros = no command.
MSG_OVERRIDE46002 (SUB)ctrl → robot20 B1 double: 0.0 OFF / 1.0 ON (≥ 0.5 = ON). Latched, self-releasing.
JOINT_STATE_NAMES (fixed relay order, 25 joints; gripper indices bold)
idx 0–7arm_r_joint1…7 · gripper_r_joint1 (7)right arm + gripper
idx 8–15arm_l_joint1…7 · gripper_l_joint1 (15)left arm + gripper

6 · Gating & control semantics (the rules that make the data matter)

6.1 Delta-vs-absolute goal duality

/spacemouse/<arm>/ee_target_pose is incremental — the solver accumulates/re-bases by differencing consecutive goals, so a dropped goal only loses a step, never the reference. /quest/<arm>/ee_target_pose (whether from joy_hand or the gateway’s ControlCmd forward) is an absolute map-frame pose that replaces the internal goal directly. The mapper’s /spacemouse/<arm>/ee_target_delta publishes explicitly — after lock/limit-profile clamps — the same quantity the solver recovers internally, and it is that clamped delta that rides the ZMQ Priv rail as EEDelta. Whichever topic delivered the last goal decides the leash.

Invariant (accum/leash): clip_target must never re-base accum_* — that invariant is what makes the limit-profile box enforce correctly. Re-bases happen only at the events in §6.3.

6.2 control_override gate

When /control_override is TRUE, joy_hand stops publishing /spacemouse/<arm>/ee_target_pose entirely — the solver then sees only the absolute rail (/quest/<arm>/ee_target_pose), i.e. ZMQ/gateway or the physical quest. The override Bool is owned by the gateway: ZMQ clients send MSG_OVERRIDE instead of touching the topic directly.

6.3 Re-base events (ee_goal_ ← achieved pose)

  • BASE → ARM switch (/teleop_mode)
  • /control_override release edge (TRUE → FALSE)
  • /teleop/pose_changed — pose load / home reset completed by the solver
  • /teleop_resync — joint-state recovery (waits for an achieved pose stamped after the resync)
  • Quest engage — but only if achieved pose age ≤ quest_achieved_max_age_s = 0.5 s

6.5 Gripper mapping (§11) — TRACK-gated

Read under pose_mutex_, applied only while the quest is in TRACK (in APPROACH the 4-way engage hold keeps trigger ≥ 0.5, so it is deliberately ignored; non-TRACK uses SpaceMouse button increments from /{left,right}/joy):

gripper_l_pos_ = clamp01(trigger_l)              * kGripperLMax          # 0.0 … 1.2
gripper_r_pos_ = kGripperRMin + clamp01(trigger_r) * (kGripperRMax − kGripperRMin)  # 0.175 … 1.2

The gateway speaks the same normalized 0…1 trigger language (clamp01) and reports achieved openings back normalized against _GRIP_OPEN {0: 0.175, 1: 0.0} / _GRIP_CLOSED {0: 1.2, 1: 1.2} per arm index (0 = right, 1 = left).

6.8 Obs / Priv emission rules

Obs (6001): sent only when both achieved EE poses and the first /joint_states are present and all values finite — a zero-filled joint block would be worse than silence. Once resolved, one complete self-contained Obs per tick (joint block repeats newest /joint_states between broadcasts). Priv (6003): fixed cadence once cam_tf is known; EEDelta zero-filled per stale arm (§6.6). Both PUB rails have no CONFLATE — every tick is a complete observation for sync-and-concat consumers.
